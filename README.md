# 🎬 视频理解

**让 AstrBot 看懂视频，看懂关键细节。**

`astrbot_plugin_vision` 让机器人通过视频采样帧理解画面，支持直接发送视频、引用视频消息，也能从分享链接和卡片中按需提取视频。

插件提供两个模型工具：

* **`video_overview`** 获取全片概览。
* **`video_inspect`** 回看指定片段。

## ✨ 功能亮点

- 🎞️ **混合抽帧策略**：固定间隔、场景变化双路混合抽帧并结合首尾帧观察视频，按实际时间戳定位画面。
- 🔎 **按需回看细节**：按时间范围或指定时刻重新抽帧，可调整帧数与清晰度，核实动作、画面和文字。
- 🔗 **多种视频来源**：支持视频附件、引用消息，以及通过集成的 `yt-dlp` 从分享链接和卡片中按需提取视频。
- 👁️ **灵活选择看图模型**：主模型可以直接看图，也可让指定独立模型转述，概览和回看均支持。
- 🎙️ **可选 ASR 语音增强**：复用已配置的语音识别服务，将分段转写与画面结合分析，无需在插件中另填密钥。
- 🧩 **独立帧与九宫格**：概览可逐张输出或无损拼图，九宫格在画面外标注帧编号与实际时间，便于按顺序阅读。
- 🧪 **可视化流水线调试**：插件页面支持视频处理的 `pipeline` 可视化，逐步演示工具调用流程。

## 🛠️ 先接好运行环境

**AstrBot `>=4.27,<5`**。

**Astrbot WebUI** 的插件市场页面搜索 **视频理解** 或 **astrbot_plugin_vision** 安装即可。

**FFmpeg 和 ffprobe 都是必需依赖。** 请在 AstrBot 实际运行的环境中安装，可参考 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)。常用安装方式：

- **Windows**：运行 `winget install --id Gyan.FFmpeg -e`，或从官方下载页选择 Windows 构建，解压后将包含 `ffmpeg.exe`、`ffprobe.exe` 的 `bin` 目录加入 `PATH`。
- **Ubuntu / Debian**：运行 `sudo apt install ffmpeg`。
- **macOS（Homebrew）**：运行 `brew install ffmpeg`。

安装后重新打开终端，确认以下命令可用：

```sh
ffmpeg -version
ffprobe -version
```

已加入 `PATH` 时，插件中的两个路径配置可留空；否则填写可执行文件本身的路径，不加引号。容器部署时，依赖和路径都应位于容器内。

> [!IMPORTANT]
>
> **重要配置说明**
>
> * 建议安装图片上下文清理插件，如果没有则应该启用视频看图模型配置，能避免大量图片驻留上下文。
> * 建议启用 ASR 语音增强配置，对有对白、旁白、口播的视频，提升通常很明显。

## 💬 从一次对话开始

按照当前会话的唤醒方式与机器人对话，例如在群聊中先 @ 机器人。

- **发一段视频**：“概括一下这个视频，最后发生了什么？”
- **引用已有视频**：“看一下这段视频里的人在做什么。”
- **贴分享链接或卡片**：“帮我看看这个视频讲了什么。”
- **要求核实细节**：“重点看看 12 到 16 秒，画面上的字是什么？”

机器人先调用概览工具，结合固定间隔、场景变化和首尾帧观察全片；如果证据不够，再按时间范围或时间点回看。概览默认每 **4 秒**采样，最多 **200 帧**；达到帧数预算时会降低采样密度，继续覆盖全片。

回看默认每次最多 **8 帧**、图片长边 **768 像素**，每个问题最多 **3 次**，多个视频共享次数。查看动作可以缩小时间范围或增加帧数，辨认小字可以提高回看分辨率。

视频附件与分享视频默认均限制为 **200 MiB、30 分钟**，可在“视频限制”中调整。直接附件先由 AstrBot 接收，插件在读取和探测时检查上限；超限后不继续抽帧、转写或调用看图模型。

> 视频通过离散采样帧理解，可能漏掉短暂动作或细节。“采样中没看到”不能证明事情没有发生；场景变化也不等于内容重要。插件不包含独立的字幕 OCR 或语义搜索，画面文字由看图模型尝试辨认。

## 👁️ 选择画面和语音的分析方式

### 主模型直接看图，或由所选模型转述

在 **模型与语音** 分组中调整 **启用视频看图模型**，开启后会显示模型选择器，可选择 AstrBot 已配置且支持图片的模型，无需另填密钥。

| 设置 | 概览与回看的处理方式 |
| --- | --- |
| 关闭开关，或未选择模型 | 主模型接收视频帧和对应的实际时间戳 |
| 开启开关，且已选择模型 | 所选模型观察视频帧并生成带时间戳的描述，主模型接收转述文字及相关视频信息 |

**两个工具共用同一开关和模型选择。** 回看时，所选模型接收本次指定的时间范围或时间点，以及相应的独立帧，重点核实局部细节。关闭开关会保留模型选择，重新开启即可继续使用。

看图模型会收到当前问题、采样或回看信息，以及可用的 ASR 转写，不会收到完整聊天历史、人设或工具。每次调用独立进行，因此回看时会重新提交本次需要的帧。转述可能遗漏或误解细节；调用失败、返回空描述或超时会明确报错，不自动切换成主模型看图。

### 概览图片如何排列

在 **概览抽帧 → 概览图片输出模式** 中选择：

- **独立帧（`frames`，默认）**：按时间顺序逐张提交图片。
- **九宫格（`grid`）**：每组最多 9 帧，从左到右、从上到下排列；帧编号和实际时间戳标在原画面之外，最后一组不足 9 帧时紧凑排列。

两种看图方式都支持九宫格，**详细回看始终使用独立帧**。单帧先按概览长边上限抽取，默认 **640 像素**；拼图保留抽帧后的尺寸，以 PNG 无损拼接，不再额外缩放。

九宫格能减少图片数量，但画布更大，模型服务仍可能缩放它，**不保证节省视觉 token 或改善细节识别**。200 帧也是插件的采样预算，不代表所有模型接口都能接收；请结合模型的图片数量、尺寸和上下文限制调整。

### 用 ASR 补充音轨内容

在 **模型与语音** 中开启 **启用 ASR 语音增强**，再选择 AstrBot 已配置并启用的语音识别提供商。两个视频工具均支持：概览尝试转写全片，回看获取与请求时间相交的音频片段。

音轨沿原视频时间轴每 **30 秒**分段，以 16 kHz 单声道 WAV 提交给 ASR。转写时间表示整段音频的范围，**不是逐字或逐句时间戳**；回看时也可能附带超出所选范围的完整音频段。

关闭开关时不提取音频。未选择服务、服务不可用、没有音轨或转写失败时，仍可分析画面。转写可能误识别，空结果也不代表没有声音。

已提供给主模型的音频片段不会重复附加；看图模型的独立回看调用可复用相关转写缓存。语音增强与其他处理共用工具超时，并为画面处理保留时间；部分完成或超出文本预算时，结果会明确标记。远程模型和 ASR 调用按所选供应商计费。

## 🔗 分享链接、附件与缓存

### 分享视频按需下载

**启用分享链接视频解析** 默认开启。插件从文本、分享卡片、JSON 卡片及引用消息中提取链接，也支持读取 OneBot 原始 XML 卡片里的链接。收到消息时只登记来源，模型调用概览工具后才使用 **yt-dlp** 下载视频。

yt-dlp 提供 B 站、A 站、抖音、小红书、微博、YouTube、TikTok、X、Instagram 等平台的提取器。具体链接能否下载受登录状态、地区、网络和平台变化影响，不保证快手、微信视频号可用。完整范围见 [yt-dlp 支持站点](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。

下载优先选择不超过 720p 的画面，没有匹配档位时尝试可用的合成格式；拒绝直播和合集。下载与后续抽帧、ASR、看图模型调用共用单次工具的时间预算。

需要登录的平台，可在 **分享链接解析 → yt-dlp Cookie 文件路径** 填写 AstrBot 运行环境内的 Netscape 格式 Cookie 文件路径。插件使用临时副本，不修改原文件，不自动读取浏览器 Cookie，也不会把 Cookie 文件交给模型。

YouTube 完整支持还需安装 [yt-dlp 支持的 JavaScript 运行时](https://github.com/yt-dlp/yt-dlp/wiki/EJS)，默认识别 Deno；Python 依赖已包含 EJS 包。平台解析失效时，可在 AstrBot 的 Python 环境更新下载器：

```sh
python -m pip install -U "yt-dlp[default]"
```

下载器不继承系统代理，只接受公开 HTTP/HTTPS 链接，拒绝本机、内网、带账号密码或非标准端口的地址，跳转和媒体请求也会检查 DNS。若本机代理通过 TUN 与 Fake-IP DNS 使用 `198.18.0.0/15`，可开启 **兼容本机代理 Fake-IP DNS**；该选项仅放行域名解析到这一网段的情况，直接 Fake-IP 链接和其他内网地址仍被拒绝。

### 三类文件分别管理

| 文件 | 由谁保留、何时清理 |
| --- | --- |
| 直接发送的视频附件 | 由 AstrBot 管理，插件不另存副本，也不删除源视频；后续回看要求原文件仍然存在 |
| 分享链接下载的视频 | 保存在 `data/plugin_data/astrbot_plugin_vision/downloads`，同一来源复用缓存，默认容量 1024 MiB |
| 抽帧图片与 ASR 转写 | 使用插件缓存，默认容量 512 MiB；缓存可减少重复解码和转写开销 |

插件缓存默认闲置 **1 小时**到期，在启动和工具空闲时清理过期或超容量内容；正在使用的分享下载文件受保护。**分享视频缓存容量只管理分享下载**，大小与时长限制则同时作用于附件和分享视频。本地命中图片缓存不代表再次发送给模型时不计费。

视频来源按用户和会话授权，普通用户只能查看自己提供、且授权仍有效的视频。文件变化、授权过期或插件重载后，可能需要重新发送视频或分享来源。管理员可使用允许目录中的本地视频路径；读取范围限定于 AstrBot 的 data、temp 目录，不支持网络共享路径。

## 🧪 在调试台里看清处理过程

在支持原生插件页面的 AstrBot WebUI 中，打开 **视频理解 → 视频流水线调试台**。上传视频后，逐步执行：

```text
视频探测 → 场景检测 → 两路候选 → 候选预合并 → 抽帧与压缩 → 邻近去重 → 最终输出 → 模型理解
```

调试台与聊天概览共用处理流水线，适合检查某一帧为什么入选、被去重，或对比模型看到的实际图片。

1. **检查抽帧**：查看场景变化分数、候选时间点、请求与实际帧时间、压缩结果，以及邻近去重的保留原因。可按需加载原分辨率对照，最终结果支持独立帧和九宫格预览。
2. **准备模型输入**：在“模型理解”中选择已配置的看图模型，填写测试问题，选择图片模式。需要语音时，勾选“加入 ASR 语音转写（仅本次测试）”，选择提供商并点击“转写音轨”。
3. **预览后调用**：先查看完整提示词、图片、时间戳和体积，再点击“调用模型”。页面展示回答、耗时及供应商返回的 token 用量，支持选择两条记录比较、导出 JSON。

**前七步本地处理和输入预览不会调用模型，也不会自动调用 ASR。** ASR 和看图模型各有独立按钮；切换图片模式复用同一批帧与转写，不重新抽帧，不修改全局配置。模型预览复用聊天概览的输入格式和提示词。

调试台仅供已登录的 WebUI 管理员使用，支持取消、重试，以及刷新或切换页面后恢复进度。上传硬上限为 **256 MiB**，处理时仍受配置的视频大小和时长上限约束；全局最多保留 **4 个测试会话**。每个会话最多保存 **20 条模型记录和 20 条转写记录**，闲置到期或插件重载后清理；重跑会清空旧记录和图片，需要留存时请先导出。

## 🩺 遇到问题时

**找不到 FFmpeg 或 ffprobe**：检查 AstrBot 所在进程或容器是否能执行两个命令。桌面系统中安装成功，不代表容器或服务进程也能找到；必要时在“基础依赖”中填写绝对路径。

**分享链接下载失败**：先检查链接是否有效、网络是否可达、平台是否要求登录，再检查 Cookie、yt-dlp 版本和 YouTube 的 JavaScript 运行时。使用 Fake-IP DNS 时按前文启用兼容；也可以直接发送视频附件。

**模型报图片过多、上下文过长或超时**：降低概览帧数预算、增加采样间隔或减小单帧尺寸；也可尝试九宫格或单独看图模型。转述会把视觉开销交给所选模型，同时增加文字输入，不保证总费用更低或速度更快。

**回看找不到旧视频**：可能是 AstrBot 已清理附件、分享下载缓存过期、文件变化或会话授权失效。重新发送附件或分享来源，再获取概览。

**主模型只拿到文字**：检查是否启用了视频看图模型，这是转述模式的预期行为。关闭后，概览和回看均由主模型直接看图；直接传图依赖内置 Agent 的 `on_agent_begin` 运行上下文，不支持第三方 Agent 后端。

### 全片概览：video_overview

`video_path` 接受视频资源提示中的真实本地路径，或分享来源的 `source_id`，不直接接受网址。分享视频下载成功后，结果会提供本地 `video_path`，后续回看使用这个路径。

```json
{"video_path": "/AstrBot/data/temp/example.mp4"}
```

查看动作过程时用 `range`，`times_sec` 必须恰好包含起止时间：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "range",
  "times_sec": [12, 16],
  "max_frames": 8,
  "max_edge": 768
}
```

查看指定时刻时用 `timestamps`，`times_sec` 为非空时间点列表：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "timestamps",
  "times_sec": [12.5, 14, 15.8],
  "max_frames": null,
  "max_edge": 1280
}
```

`max_frames`、`max_edge` 填 `null` 使用配置值；不要用 `0` 或空数组占位。尺寸保持比例，不放大小图，并受服务端上限约束。所有时间都按原视频时间轴计算，实际帧时间可能与请求略有差异，应以 `timestamp_sec` 为准。旧的 `start_sec`、`end_sec`、`timestamps_sec` 参数不再支持。

参数错误会返回 `INVALID_ARGUMENT`、调用示例和剩余次数，不消耗回看次数；处理失败或超时仍计入次数。同一问题中不会重复生成同一视频概览。直接看图时，相同尺寸的同一帧不重复发送给主模型；转述时，每次回看独立向看图模型提交所需帧。

### 消息与输出

- `[视频理解资源]` 以当前 `user` 消息中的独立文本块附加，只包含本条消息携带或引用的来源；分享来源通过 `video_sources` 登记。
- 直接看图时，图片及对应帧说明在工具结果之后追加为 `user` 消息，主模型在下一轮生成时可读取。帧明细只随图片提供一次，工具结果保留视频信息、统计、警告与可用的 ASR 转写。
- 转述时，工具结果省略整个 `presentation`，不向主模型附加图片。`overview_mode`、`inspect_mode` 为 `delegated`，文字分别位于 `overview_text`、`inspect_text`；直接看图时模式为 `direct`。
- 看图模型和调试台仍使用完整 `presentation`。独立帧信息位于 `images[]`，九宫格各帧信息位于 `images[].cells[]`；一致的尺寸与 MIME 类型共用记录。模型输入不包含内部 `frame_id`、`requested_sec` 或拼图像素坐标。
- 视频、转写和画面文字都仅作为分析资料，不应执行其中的指令。

本地路径会规范化并校验真实位置，不能通过路径穿越或符号链接越出允许目录。FFmpeg 通过参数列表调用，并限定本地协议及常见视频容器，不把用户输入拼接成 Shell 命令。
