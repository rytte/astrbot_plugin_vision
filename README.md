# 视频理解 · astrbot_plugin_vision

为 AstrBot 主对话模型提供两个工具：先获取视频概览，再按需要回看指定时间段。默认由主模型直接看图，也可从 AstrBot 已配置的模型中指定视频看图模型，并可选用已配置的 ASR 转写视频语音，无需在插件中另填 API Key。

## 工作方式

```text
接收视频附件，或在需要概览时下载分享链接中的视频
    → 固定间隔帧 + 场景变化候选 + 边界帧
    → 邻近去重、时间覆盖检查、帧数预算
    → 默认将图片及真实时间戳交给主模型
      或由指定看图模型生成文字概览，再交给主模型
    → 证据不足时按时间点或时间段回看，沿用相同看图方式
```

- 概览默认每 **4 秒**采样，最终最多 **200 帧**，图片长边最多 **640 像素**。
- 概览可选独立帧或九宫格输出。九宫格每组最多 9 帧，以 PNG 无损拼接，保留正式抽帧后的像素尺寸，画面外标注帧编号和实际时间戳；详细回看仍使用独立帧。
- 超预算时增大固定间隔，仍覆盖全片，不直接丢弃后半段。
- 场景变化检测在本地完成；候选不等于编码关键帧，也不保证语义重要。
- 时间接近且内容相似时，优先保留清晰、有效的变化帧；存在明显差异或会破坏覆盖时保留必要帧。不对全片做无条件相似帧去重。
- 回看默认最多 **8 帧**、长边 **768 像素**；每个问题最多 **3 次**，多个视频共享次数。参数校验失败返还次数；处理失败或超时仍计入次数，避免无限重试。
- 主模型直接看图时，概览和回看的真实图片通过 AstrBot 内置 Agent 的运行上下文传入主模型，每张图片前附帧信息和时间戳；工具结果返回视频信息、采样及呈现统计、警告、剩余额度和可选 ASR 转写，不重复帧明细，也不触发核心为 `ImageContent` 添加的缓存路径及“满意后发给用户”提示。
- 图片先暂存在当前 Agent 的消息缓冲中，等核心写入本批工具调用及全部结果后，再追加为独立的 `user` 图片消息，随后恢复普通消息列表。模型输入和保存历史均保持此顺序，无需修改 AstrBot 核心文件；此对接依赖当前内置 Agent 批量追加工具消息的行为。
- 视频资源提示作为当前 `user` 消息中的独立 `text` 块添加，只包含本条消息携带或引用的视频；后续消息不会重复附加缓存中的旧路径。授权有效期内仍可使用对话历史中的路径回看。
- ASR 语音增强默认关闭；开启并选择可用的语音识别提供商后，工具附带按时间分段的音轨转写。无音轨、提供商不可用或转写失败时仍返回画面分析所需的信息。

## 安装

1. 使用 AstrBot `>=4.27,<5`，将本仓库作为插件安装到 `data/plugins/astrbot_plugin_vision`。
2. 安装 `requirements.txt` 中的 Python 依赖。
3. 在 **AstrBot 实际运行环境**安装 FFmpeg，确保同时包含 `ffmpeg` 和 `ffprobe`。容器部署必须安装在容器内，而不是只安装在宿主机。
4. 使用 AstrBot 内置 Agent，确认主模型支持工具调用，直接看图时还需支持图片，并启用 `video_overview`、`video_inspect`。直接看图依赖 `on_agent_begin` 提供的运行上下文传入视频帧；缺少该上下文时明确报错，不支持第三方 Agent 后端。

检查依赖：

```text
ffmpeg -version
ffprobe -version
```

默认从 `PATH` 查找，也可在插件配置中指定 `ffmpeg_path`、`ffprobe_path`。路径填写可执行文件本身，不要填写带参数的命令，也不需要额外加引号。

## 使用

直接向机器人发送视频并提出问题。插件在模型请求前读取视频附件的本地路径，通过 `extra_user_content_parts` 将 `[视频理解资源]` 提示作为同一条 `user` 消息中的独立文本块添加，用户原文保留在原文本块中，不主动进行模型分析。引用消息里的视频、常见视频扩展名的文件附件也会尝试读取。

直接附件与分享视频统一受“视频大小上限”和“视频时长上限”约束，默认单片最多 **200 MiB、30 分钟**，概览与回看均生效。附件先由 AstrBot 接收，插件读取或探测时检查上限，超限则返回原因，不再抽帧、转写或调用视频看图模型。附件源文件继续由 AstrBot 管理，插件不另存副本；“分享视频缓存容量”只统计插件下载的完整视频文件。

### 分享链接和卡片

默认开启 **“启用分享链接视频解析”**。可发送含链接的分享文案、分享卡片、JSON 卡片，或引用包含这些内容的消息；OneBot 原始 XML 卡片也可提取链接。插件只登记来源，主模型需要查看时才通过 `video_overview` 调用 yt-dlp 下载，不会收到链接就自动下载。

`[视频理解资源]` 中会增加 `video_sources`，每项有 `source_id` 和展示地址。模型将 `source_id` 填入 `video_overview.video_path`，下载成功后使用结果中的真实本地 `video_path` 调用 `video_inspect`。无需增加模型工具，独立帧、九宫格、视频看图模型和 ASR 均复用现有流程。原始卡片的签名参数保留在内部，新增提示中的展示地址不含查询参数。

- 默认单片最多 **200 MiB、30 分钟**，优先下载不超过 720p 的画面；没有此档位时尝试可用的合成格式。拒绝直播和合集，时长已知时下载前检查，下载后再通过 ffprobe 核验。下载、抽帧、ASR 和视频看图模型共用 `tool_timeout`；失败或取消会终止下载进程并删除本次临时文件。
- 下载存放在 AstrBot `data/plugin_data/astrbot_plugin_vision/downloads`，同一来源复用缓存。默认容量 **1024 MiB**，闲置期限沿用 `cache_ttl`；仅在启动和工具空闲时清理，正在使用的文件受保护。清理后需要重新发送来源或重新获取概览；聊天附件源文件不会被删除。
- yt-dlp 提供 B 站、A 站、抖音、小红书、微博、YouTube、TikTok、X、Instagram 等平台的提取器。**是否能下载取决于具体链接、登录、地区和平台变化**；不保证快手、微信视频号可用。短链由 yt-dlp 跟随跳转解析，列表见 [官方支持站点](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。
- 需要登录时，可在 **“yt-dlp Cookie 文件路径”** 填写 AstrBot 运行环境内的 Netscape 格式 Cookie 文件路径。文件不会传给模型，下载使用临时副本，不修改原文件。插件不会自动读取浏览器 Cookie。
- `requirements.txt` 包含 `yt-dlp[default]` 及 YouTube 所需的 EJS 包；完整 YouTube 支持还需要安装 [官方支持的 JavaScript 运行时](https://github.com/yt-dlp/yt-dlp/wiki/EJS)，默认识别 Deno。下载器不继承系统代理，不接受本机、内网、带账号密码或非标准端口的链接；跳转和媒体请求也检查 DNS 地址。FFmpeg 仅处理下载后的本地文件。
- 若本机代理通过 TUN 和 Fake-IP DNS 将公网域名解析成 `198.18.x.x` 或 `198.19.x.x`，可开启 **“兼容本机代理 Fake-IP DNS”**。该选项仅允许域名连接到 `198.18.0.0/15` 虚拟地址，其他内网地址及直接 Fake-IP 链接仍被拒绝；开启后真实目标的解析由本机代理负责。默认关闭，检测到此情况会明确提示。

平台解析失效时，可在 AstrBot 的 Python 环境运行 `python -m pip install -U "yt-dlp[default]"` 更新。下载失败会明确返回错误，仍可直接发送视频附件使用。

### `video_overview`

```json
{"video_path": "/AstrBot/data/temp/example.mp4"}
```

返回视频元信息、采样策略、预算是否导致降采样、实际最大采样间隔，以及按时间排序的图片。每张图片附带实际时间 `timestamp_sec` 和入选原因，模型按时间戳引用画面。独立帧尺寸一致时，宽高只在 `presentation.frame_width/frame_height` 写一次，`presentation.images[]` 不再逐张重复；尺寸不一致时才逐张记录。视频看图模型的输入和调试台的模型预览共用该格式。模型输入和两个工具的输出均不包含 `frame_id`、`requested_sec`；帧标识仅用于内部去重、缓存和调试，请求时间仍保留在内部抽帧记录与调试台的“请求 → 实际”对照中。

同批图片格式一致时，`mime_type` 只在 `presentation.mime_type` 写一次，各图片说明不再重复；混合格式时才逐张记录。该规则覆盖独立帧、九宫格、直接看图、视频看图模型的输入及局部回看。

主模型直接看图时，帧明细只在 `user` 图片消息中提供一次，每张图片紧邻对应说明；每组消息开头用 `tool`、`video_path` 标识来源，便于区分同批调用的多个视频。`tool` 结果不再包含 `frames`、`presentation.images` 或 `skipped_already_seen` 明细，已看过而跳过的帧仅通过 `skipped_already_seen_count` 返回数量。指定视频看图模型时，主模型的工具结果保留带时间戳的文字描述、视频元信息、采样或回看请求及可用的 ASR 转写，省略整个 `presentation`，也不额外返回顶层 `frames` 列表。完整的 `presentation` 仍供看图模型输入和调试使用：独立帧直接在 `images[]` 中记录时间戳、入选原因和帧编号；九宫格在 `images[].cells[]` 中记录各格信息，每帧只记录一次。

在插件配置中打开 **“启用视频看图模型”**，下方才显示 **“视频看图模型”**，可使用 AstrBot 原生模型选择器选择已配置且支持图片的模型。保存并重载插件后生效：

- **开关关闭（默认）或未选择模型**：主模型直接接收概览和回看图片，`overview_mode`、`inspect_mode` 为 `direct`。关闭后保留模型选择，重新开启即可使用；已有配置也需打开此开关才会调用视频看图模型。
- **开关开启且已选择模型**：概览和回看都由指定模型观察视频帧，结合实际时间戳、当前问题以及本次采样或回看请求生成文字；主模型不接收视频帧，工具结果省略 `presentation`，`overview_mode`、`inspect_mode` 为 `delegated`。概览文字位于 `overview_text`，回看文字位于 `inspect_text`。
- 两个工具共用同一个开关和模型选择。概览支持独立帧或九宫格；回看始终以独立帧提交给看图模型，按 `mode`、`times_sec`、`max_frames` 和 `max_edge` 核实局部细节。
- 指定模型不接收完整聊天历史、人设或工具。其描述属于二手观察，可能遗漏或误解细节，需要时应缩小回看范围、增加帧数或提高分辨率核验。
- 模型调用失败、返回空描述或超时会明确报错，**不会自动回退成主模型看图**，避免意外的大量图片输入。抽帧和模型调用共用单次工具超时。

在 **“概览图片输出模式”** 中选择 `frames`（默认独立帧）或 `grid`（九宫格）。两种看图模型配置均支持九宫格：按时间顺序，每组最多 9 帧，从左到右、从上到下排列；末组不足 9 帧紧凑排列，不重复补帧。帧编号和真实时间戳位于额外标签栏，`cells` 记录每格的帧编号、时间戳及行列。同一张拼图内帧尺寸一致时，只在拼图层的 `frame_width`、`frame_height` 写一次，各格不重复 `width`、`height`；实际存在混合尺寸时才逐格记录尺寸。拼图本身的 `width`、`height` 仍表示整张画布。像素坐标 `x`、`y` 仅在拼图绘制时计算，不写入模型输入或调试输出。直接看图时，`cells` 位于每张拼图前的说明中；指定视频看图模型时，映射位于该看图模型输入的 `presentation.images[].cells` 中，调试台模型预览共用相同结构，图片诊断详情可另查内部帧标识。`sampling.returned_count` 仍表示帧数，`submitted_image_count` 表示实际提交给模型的图片数。

拼图保留的是 `overview_max_edge` 缩放抽帧后的像素尺寸，**拼接时不再缩放，也不重新进行有损编码**；源视频到单帧的既有缩放和 JPEG 编码步骤仍然存在。编号和边框会增加总像素，PNG 也可能比独立 JPEG 总体积更大。`max_edge_limit` 约束单帧长边，拼接画布不套用该限制，单张拼图最多 3200 万像素，超出会明确报错；请按模型的大图输入能力选择模式。九宫格可减少图片数量，但**不保证减少视觉 token 或改善细节识别**，模型服务仍可能再次缩放大图。

### ASR 语音增强（可选）

在插件配置中打开 **“启用 ASR 语音增强”**，下方才会显示 **“ASR 语音识别提供商”**。使用 AstrBot 原生选择器，从已配置的语音识别（STT/ASR）提供商中选择；保存并重载插件后生效。

- 开关关闭时不提取音频，也不调用 ASR。开启但未选择提供商，或所选提供商未加载、已禁用、类型不符时，仅分析画面，不自动选择其他模型。
- `video_overview` 尝试转写全片第一条音轨；`video_inspect` 获取与请求时间范围或时间点相交的音频片段。音轨按原视频时间轴每 **30 秒**分段，以 **16 kHz 单声道 WAV** 交给所选提供商。最后一段按视频时长截取，回看可能附带超出所选范围的完整音频段。
- AstrBot 通用 STT 接口只返回文本，因此 `asr.segments[].start_sec/end_sec` 表示**音频分段范围，不能视为逐字或逐句时间戳**。转写可能误识别，空转写也不证明没有说话或其他声音。
- 直接看图时，转写仅在工具结果的 `asr` 中提供一次，不再复制到 `user` 图片消息。指定视频看图模型时，该模型也会接收本次相关转写辅助观察；独立的回看调用可复用已转写的缓存，主模型仍只接收尚未提供的分段转写。两种图片输出模式均支持。
- 同一问题中已经提供的音频段不重复附加；新问题可从缓存读取。缓存按视频文件身份、ASR 提供商及其配置、模型区分，并沿用 `cache_ttl`、`cache_max_mb` 清理规则；密钥不写入缓存内容。临时 WAV 在成功、失败、超时或取消时删除。
- ASR 与抽帧、概览模型共用 `tool_timeout`，转写最多使用剩余时间的一半且不超过 **60 秒处理时间**，为画面处理保留预算；单次输出最多 **24000 字符**。时间不足、达到文本上限或中途失败时，通过 `status`、`complete` 和提示明确标记不完整结果，保留已经完成的转写及画面，不将部分转写当成全片记录。
- 聊天中的两个视频工具可自动附加转写；调试台可在“模型理解”中显式转写并测试。调试台的本地流水线、输入预览和状态轮询均不调用 ASR，只有点击“转写音轨”才会执行。远程 ASR 会按供应商配置发送音频并可能产生费用；本地 ASR 沿用 AstrBot 的运行环境。

### `video_inspect`

查看动作过程：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "range",
  "times_sec": [120, 124],
  "max_frames": 8,
  "max_edge": 768
}
```

核实指定时刻：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "timestamps",
  "times_sec": [120.5, 121.8, 123],
  "max_frames": null,
  "max_edge": 1280
}
```

`mode` 必须明确选择 `range` 或 `timestamps`：前者的 `times_sec` 恰好包含起止时间，后者为非空时间点列表。工具 Schema 显式声明模式枚举、必填字段和可为空的可选参数；`max_frames`、`max_edge` 填 `null` 使用插件配置值，不填 `0` 或空数组占位。

旧的 `start_sec`、`end_sec`、`timestamps_sec` 调用格式已移除，没有兼容别名；已有工具调用脚本需要改用 `mode`、`times_sec`。升级后重载插件，并在新问题中调用以使用更新后的工具定义。

所有时间以原视频时间轴为准，从 0 秒开始；实际帧可能略晚于请求时间，尾部可能回退至可读取的帧，因此应以返回的 `timestamp_sec` 为准。重复落到同一帧时只返回一次。参数错误返回 `INVALID_ARGUMENT`、正确调用示例和剩余回看次数，不消耗抽帧额度；处理失败或超时仍计入次数。

`max_edge` 是模型请求的图片最长边上限，保持比例、不放大小图，并受服务端硬上限约束。查看小字可以提高尺寸；没采到动作过程则应缩小时间范围或增加采样帧数。主模型直接看图时，同一问题内已返回的相同尺寸、相同画面帧不会重复送图；指定视频看图模型时，每次回看会重新提交本次所需帧，因为各次模型调用不共享历史。两种模式下相同视频概览均不会重复生成，回看仍受次数上限约束。

## 流水线调试台

在支持原生插件页面的 AstrBot WebUI 中，重载插件后打开 **视频理解 → 视频流水线调试台**，上传视频，再逐次点击右上方的执行按钮：

```text
视频探测 → 场景检测 → 两路候选 → 候选预合并 → 抽帧与压缩 → 邻近去重 → 最终输出 → 模型理解（可选）
```

- 每次点击只执行下一个阶段；已完成的阶段可随时切换查看。页面与 `video_overview` 共用同一条处理流水线。
- 场景检测展示变化分数、阈值及窗口取舍。长视频曲线最多保留 2000 个时间窗的峰值；阈值候选明细最多记录前 4000 条，实际筛选仍处理全部候选。
- 两路候选分别展示固定间隔及首尾帧、场景变化帧，并共用视频时间轴。候选小图按需额外抽取，长边最多 240 像素；正式抽帧发生在预合并之后。
- 正式抽帧展示请求及实际时间、输出尺寸、JPEG 体积。点击图片可查看压缩结果、实际去重指纹，并按需加载原分辨率 JPEG 对照。场景检测的 `160×160` 缩放、正式输出的长边限制、`32×18` 灰度指纹分别解释。
- 邻近去重可逐对查看画面差异、质量分、时间覆盖上限和保留原因。最终结果展示来源统计、最大时间空隙、图片总体积，并支持导出 JSON 调试记录。
- 可选择独立帧或九宫格后重跑；最终输出展示实际发送图片数、总像素、输出体积和九宫格预览。点击拼图可切换原始像素查看，核对每格的帧编号、实际时间和尺寸。
- 第八阶段 **“模型理解”** 可选择 AstrBot 已配置的看图模型、输入测试问题，并独立选择本次使用独立帧还是九宫格。两种图片模式复用同一批最终保留帧，切换不重新抽帧，也不改变全局配置。已明确关闭图片输入的模型不会出现在列表中；未标注图片能力的模型会提醒需自行确认支持。
- 可勾选 **“加入 ASR 语音转写（仅本次测试）”**，选择已启用的语音识别提供商，再点 **“转写音轨”**。页面展示分段范围、转写文本、耗时和缓存命中；先确认转写，再预览并调用看图模型。默认继承插件 ASR 配置，本次选择不修改全局配置；切换图片模式复用转写，关闭此项可用相同画面和问题进行对照。转写复用聊天工具的分段、缓存和时间预算，支持取消与重试；无音轨或转写失败时仍可测试画面。
- 先点 **“预览模型输入”**，查看实际输入图片、尺寸、体积、帧时间戳，以及完整系统和用户提示词；再单独点 **“调用模型”**。前七步、输入预览及查看历史都不会调用模型。页面复用聊天工具中指定概览模型的提示词与调用入口，不附加人设、聊天历史或工具。
- 调用后展示回答、耗时及 AstrBot 返回的输入、输出、缓存输入与总 token 用量；未提供的字段显示 **“未提供”**，不估算视觉 token。每次调用保存模型、问题、图片模式、是否加入 ASR、实际输入和结果，可选两条记录并排比较，也可导出包含转写记录的全部 JSON。普通状态轮询不重复传输转写原文、完整提示词和回答。
- 支持取消、失败重试和页面刷新后恢复记录；重复提交同一个调用或转写编号不会重复执行。每个测试会话最多保留 **20 条模型调用记录和 20 条转写记录**，重跑本地流水线会清空记录和旧图片，可先导出留存。
- 切换 WebUI 页面或刷新后，自动恢复上次测试、查看阶段、参数、模型问题与 ASR 选项草稿、分页、去重比较位置和选中的调用记录；后台任务继续执行，输入预览恢复时不会调用模型或 ASR。页面状态通过插件后端按管理员保存，与测试会话一同过期或清理。若需继续播放源视频，可重新选择原文件关联本地播放器，无需再次上传或重跑。
- 左侧参数只用于本次测试，应用后从头重跑；支持取消当前阶段、恢复仍有效的测试会话，以及手动删除。重跑清理旧调试图片，防止旧页面或旧参数混入新结果。

调试台仅供已登录的 WebUI 管理员使用，模型调用使用所选模型的已配置凭据。视频上传限制为 **256 MiB**，处理时也受配置的视频大小与时长上限约束，全局最多保留 **4 个测试会话**；每个会话的图片缓存上限为 `cache_max_mb` 与 **512 MiB** 中较小者。测试文件闲置 `cache_ttl` 秒后清理（最长 1 小时），插件卸载或重载时清理本次测试文件和记录，不删除聊天中提供的源视频。本地处理、额外预览及每次模型调用分别计时；本地处理共用 `tool_timeout` 时间预算，每次模型调用单独使用该超时，均不计手动查看阶段的停顿。调用失败或取消后保留本地帧；供应商可能已经处理请求，是否计费以供应商为准。

## 配置

配置界面分为 **基础依赖、视频限制、分享链接解析、模型与语音、概览抽帧、详细回看、运行与缓存** 七组。FFmpeg 和 ffprobe 为必需依赖，已加入 `PATH` 时可留空路径。分享解析、视频看图模型和 ASR 的相关选项仍按开关展开。配置文件采用分组结构，例如 `dependencies.ffmpeg_path`、`model_enhancement.asr_enabled`；下表列出各组内的配置键名。本次调整不迁移旧版平铺配置。

| 配置 | 默认值 | 用途 |
|---|---:|---|
| `ffmpeg_path` / `ffprobe_path` | 空 | 留空从 PATH 查找 |
| `share_links_enabled` | `true` | 识别分享链接及卡片，按需下载视频 |
| `download_max_mb` | 200 | 视频大小上限，适用于直接附件和分享视频，单位 MiB |
| `download_max_duration` | 1800 | 视频时长上限，适用于直接附件和分享视频，单位秒 |
| `download_cache_max_mb` | 1024 | 仅分享视频的下载缓存容量，单位 MiB |
| `download_cookie_file` | 空 | 可选 Netscape 格式 Cookie 文件路径 |
| `download_allow_fake_ip` | `false` | 兼容本机代理将公网域名解析为 `198.18.0.0/15` 虚拟地址 |
| `overview_model_enabled` | `false` | 启用视频看图模型，用于概览和回看；关闭时由主模型直接看图 |
| `overview_provider_id` | 空 | 视频看图模型，使用 AstrBot 已配置模型的选择器；开关开启且已选择时调用 |
| `asr_enabled` | `false` | 启用 ASR 语音增强，并显示提供商选择项 |
| `asr_provider_id` | 空 | 从 AstrBot 已配置的 STT/ASR 提供商中选择；开启且所选提供商可用时启用转写 |
| `overview_output_mode` | `frames` | `frames` 独立帧；`grid` 每组最多 9 帧无损拼接，仅影响概览 |
| `overview_interval` | 4 | 概览默认间隔，单位秒 |
| `overview_max_frames` | 200 | 概览总帧数上限 |
| `overview_max_edge` | 640 | 概览图片长边像素上限 |
| `scene_threshold` | 0.3 | 场景变化阈值，越低越敏感 |
| `inspect_max_frames` | 8 | 单次回看帧数硬上限 |
| `inspect_max_edge` | 768 | 回看默认图片长边上限 |
| `max_edge_limit` | 1280 | 所有单帧尺寸请求的长边硬上限，九宫格保留各帧尺寸、不额外缩放 |
| `inspect_max_calls` | 3 | 单个问题的回看次数上限 |
| `tool_timeout` | 300 | 单次工具总超时，单位秒 |
| `max_concurrency` | 2 | 工具及子进程并发上限 |
| `cache_ttl` | 3600 | 缓存闲置期限与视频授权期限，单位秒 |
| `cache_max_mb` | 512 | 空闲清理后的缓存容量上限，单位 MB |

配置项和服务端上限可按模型能力调整。**200 帧是帧数预算，不是 token 上限，也不保证所有模型接口都能接收。**独立帧每帧一张图片，九宫格每组最多 9 帧一张图片。如果模型限制图片数量、图片尺寸或上下文长度，请调整输出模式和概览预算。缓存可减少本地解码开销，不代表新问题里的图片输入不计费。

指定概览模型后，图片 token 开销转移到所选模型，主模型还会消耗文字概览及局部回看的 token。选择更便宜的看图模型可能降低费用，但多出一次模型调用，不保证总费用更低或速度更快。

## 文件和权限边界

- 视频附件由 AstrBot 消息组件落盘；分享链接由插件登记，使用 yt-dlp 按需下载。工具不接受任意网址，只接受已授权的分享 `source_id` 或真实本地路径，不支持网络共享路径。
- 仅允许读取 AstrBot 的 data、temp 目录内的本地视频；路径会规范化并检查真实位置，不能通过 `..` 或符号链接逃出允许目录。旧配置中残留的 `allowed_video_roots` 会被忽略，不影响插件加载，也不再扩展读取范围。
- 分享来源与下载后的路径都按用户和会话授权，不能借用其他用户或会话的来源。普通用户只能访问自己提供且仍在授权有效期内的视频；管理员可直接传入允许目录内的视频路径。
- 文件发生变化后，普通用户需要重新发送以授权；缓存按路径、大小和修改时间区分。
- 使用参数列表调用 FFmpeg，不拼接 Shell 命令；解码限定本地协议及常见视频容器，不接受播放列表作为输入。
- 只清理插件自己的图片、音频、转写及分享下载缓存，不删除附件源视频。上游必须保证附件回看时源文件仍存在；插件重载会清空会话授权，必要时请重新发送视频或分享来源。
- 视频内容是不可信资料，不能当作系统或工具指令。稀疏采样没有看到某事件，不足以证明事件没有发生；预算耗尽仍不确定时应明确说明。

支持可选 ASR 语音转写和视频看图模型，不包含专门的字幕 OCR、语义搜索或额外的多级视觉分析流水线。

## 开发验证

使用已安装 `requirements.txt`、AstrBot、pytest、pytest-asyncio 的环境运行：

```text
python -m pytest tests -q
ruff check .
ruff format --check .
```

测试包含采样覆盖与预算、邻近去重、路径及会话权限、回看次数、直接看图与指定模型概览、Agent 工具循环中的图片输入与提示隔离、ASR 配置与分段转写、去重与缓存、失败及取消、真实 FFmpeg 音视频处理与时间戳，以及分享卡片提取、下载缓存、DNS 拦截、子进程取消和 yt-dlp 下载本地测试服务中的样片。模型和 ASR 接口使用模拟响应，未安装 FFmpeg 时，真实视频测试会跳过。平台站点的实际可用性需结合部署网络及 Cookie 单独验证。
