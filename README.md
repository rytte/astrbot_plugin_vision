# 🎬 视频理解

**让 AstrBot 看懂视频，看懂关键细节。**

`astrbot_plugin_vision` 让机器人通过视频采样帧理解画面，支持直接发送视频、引用视频消息，也能从分享链接和卡片中按需提取视频。

插件提供两个模型工具：

* **`video_overview`** 获取全片概览。
* **`video_inspect`** 回看指定片段。

## ✨ 功能亮点

- 🎞️ **混合抽帧策略**：固定间隔、场景变化双路混合抽帧并结合首尾帧观察视频，按实际时间戳定位画面。
- 🔎 **按需回看细节**：按时间范围或指定时刻重新抽帧，可调整帧数与清晰度，核实动作、画面和文字。
- 🔗 **多种视频来源**：支持视频文件、引用消息，以及通过 `yt-dlp` 从分享链接和卡片中按需提取视频。
- 👁️ **灵活选择看图模型**：主模型可以直接看图，也可让指定独立模型转述，概览和回看均支持。
- 🎙️ **可选 ASR 语音增强**：复用已配置的语音识别服务，将分段转写与画面结合分析，无需在插件中另填密钥。
- 🧩 **独立帧与九宫格**：概览可逐张输出或无损拼图，九宫格在画面外标注帧编号与实际时间，便于按顺序阅读。
- 🧪 **可视化流水线调试**：插件页面支持视频处理的 `pipeline` 可视化，逐步演示工具调用流程。

## 🛠️ 先接好运行环境

**AstrBot `>=4.27,<5`**。

**Astrbot WebUI** 的插件市场页面搜索 **视频理解** 或 **astrbot_plugin_vision** 安装即可。

**FFmpeg 和 ffprobe 都是必需依赖。** 请在 AstrBot 实际运行的环境中安装，可参考 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)。常用安装方式：

- **Windows**：运行 `winget install --id Gyan.FFmpeg -e`，或从官方下载页选择 Windows 构建，解压后将包含 `ffmpeg.exe`、`ffprobe.exe` 的 `bin` 目录加入 `PATH`。
- **Ubuntu / Debian**：运行 `sudo apt install ffmpeg`。
- **macOS（Homebrew）**：运行 `brew install ffmpeg`。

安装后重新打开终端，确认以下命令可用：

```sh
ffmpeg -version
ffprobe -version
```

已加入 `PATH` 时，插件中的两个路径配置可留空；否则填写可执行文件本身的路径，不加引号。容器部署时，依赖和路径都应位于容器内。

> [!IMPORTANT]
>
> **重要配置说明**
>
> * 建议安装图片上下文清理插件，如 [Media 管理 - AstrBot Cloud](https://cloud.astrbot.app/plugin/rytte/astrbot_plugin_media_manager)，否则应该**启用视频看图模型**配置，避免大量图片驻留上下文。
> * 建议**启用 ASR 语音增强**配置，对有对白、旁白、口播的视频，提升通常很明显。

> [!NOTE]
>
> **Token 开销说明**
>
> * OpenAI 图片计算方式：`(宽/32)*(高/32)*1.2`，依照默认配置 640 最大边长限制，单图 token 最多 480 token。
> * 降低 token 开销：可以在配置中适当增加固定抽帧间隔，以及降低最大边长（最好是 32 的倍数，比如 480）。具体效果可以进入插件页面 `视频流水线调试台` 查看。

插件配置分为以下几组：

```text
基础依赖
模型与语音：视频分析与实时视觉共用的看图模型、ASR
通用设置：工具超时、并发上限
视频分析
├─ 视频概览
├─ 详细回看
├─ 视频限制
├─ 分享视频
├─ 使用额度
└─ 运行与缓存：单帧尺寸硬上限、缓存有效期、缓存容量
实时视觉：通用设置、设备设置、各来源的响应模式预设
```

原有配置会自动迁移到新分组并保留备份，已设置的值保持不变。

## 💬 从一次对话开始

按照当前会话的唤醒方式与机器人对话，例如在群聊中先 @ 机器人。

- **发一段视频**：“概括一下这个视频，最后发生了什么？”
- **引用已有视频**：“看一下这段视频里的人在做什么。”
- **贴分享链接或卡片**：“帮我看看这个视频讲了什么。”
- **要求核实细节**：“重点看看 12 到 16 秒，画面上的字是什么？”

机器人先调用概览工具，结合固定间隔、场景变化和首尾帧观察全片；如果证据不够，再按时间范围或时间点回看。概览默认每 **4 秒**采样，最多 **200 帧**；达到帧数预算时会降低采样密度，继续覆盖全片。

回看默认每次最多 **8 帧**、图片长边 **768 像素**，每个问题最多 **3 次**，多个视频共享次数。查看动作可以缩小时间范围或增加帧数，辨认小字可以提高回看分辨率。

视频附件与分享视频默认均限制为 **200 MiB、30 分钟**，可在“视频分析 → 视频限制”中调整。直接附件先由 AstrBot 接收，插件在读取和探测时检查上限；超限后不继续抽帧、转写或调用看图模型。

## 👁️ 选择画面和语音的分析方式

### 主模型直接看图，或由所选模型转述

在 **模型与语音** 分组中调整 **启用视频看图模型**。

| 设置 | 概览与回看的处理方式 |
| --- | --- |
| 关闭开关，或未选择模型 | 主模型接收视频帧和对应的实际时间戳 |
| 开启开关，且已选择模型 | 所选模型观察视频帧并生成带时间戳的描述，主模型接收转述文字及相关视频信息 |

**两个工具共用同一开关和模型选择。** 回看时，所选模型接收本次指定的时间范围或时间点，以及相应的独立帧，重点核实局部细节。

看图模型会收到当前问题、采样或回看信息，以及 ASR 转写，不会收到完整聊天历史、人设或工具。每次调用独立进行，因此回看时会重新提交本次需要的帧。

### 概览图片输出模式

- **独立帧（`frames`，默认）**：按时间顺序逐张提交图片。
- **九宫格（`grid`）**：每组最多 9 帧，从左到右、从上到下排列；帧编号和实际时间戳标在原画面之外，最后一组不足 9 帧时紧凑排列。

两种看图方式都支持九宫格，**详细回看始终使用独立帧**。

单帧先按概览长边上限抽取，默认 **640 像素**；拼图保留抽帧后的尺寸，以 PNG 无损拼接，不再额外缩放。

九宫格能减少图片数量，但画布更大，模型服务仍可能缩放它，**不保证节省视觉 token 或改善细节识别**。

200 帧也是插件的采样预算，不代表所有模型接口都能接收；请结合模型的图片数量、尺寸和上下文限制调整。

### 用 ASR 补充音轨内容

在 **模型与语音** 中开启 **启用 ASR 语音增强**，选择 AstrBot 已配置并启用的语音识别提供商。概览尝试转写全片，回看补充对应片段的语音内容。

音频每 **30 秒**分段转写，时间戳表示整段范围，**并非逐字或逐句时间戳**；回看时可能包含所选范围外的语音。

语音识别不可用或失败时，仍可分析画面。转写仅供参考，相关调用按所选供应商计费。

## 🔗 分享链接、附件与缓存

### 启用分享链接视频解析

默认开启。开启后插件会从文本、分享卡片、JSON 卡片及引用消息中提取链接，也支持读取 OneBot 原始 XML 卡片里的链接。

* **解析工具**：收到消息时只登记来源，模型调用概览工具后才使用 **yt-dlp** 下载视频。
* **额外适配（B站）**：B 站还支持直接发送 BV 号、av 号，以及省略 `https://` 的 `b23.tv` 短链，插件会自动补成完整链接。
* **额外适配（抖音）**：自动获取匿名访问凭据、补齐详情请求签名和媒体 Referer，通常无需登录或手动导出 Cookie；仍可能受平台风控限制。
* **视频下载**：下载优先选择不超过 720p 的画面，没有匹配档位时尝试可用的合成格式；拒绝直播和合集。
* **浏览器 Cookie**：在 **yt-dlp Cookie 文件路径** 配置填写 AstrBot 运行环境中的 Netscape 格式 Cookie 文件路径。部分平台即使无需登录也要求有效的浏览器 Cookie。插件使用临时副本，不修改原文件。
* **下载限制**：下载器不继承系统代理，只接受公开 HTTP/HTTPS 链接，拒绝本机、内网、带账号密码或非标准端口的地址，跳转和媒体请求也会检查 DNS。若本机代理通过 TUN 与 Fake-IP DNS 使用 `198.18.0.0/15`，可开启 **兼容本机代理 Fake-IP DNS**；该选项仅放行域名解析到这一网段的情况，直接 Fake-IP 链接和其他内网地址仍被拒绝。

#### yt-dlp

[yt-dlp](https://github.com/yt-dlp/yt-dlp/tree/master) 是一个开源视频下载工具，提供 **B 站、A 站、抖音、小红书、微博、YouTube、TikTok、X、Instagram 等平台**的提取器。

具体链接能否下载受登录状态、地区、网络和平台变化影响，不保证快手、微信视频号可用。完整范围见 [yt-dlp 支持站点](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。

抖音兼容处理参考 [yt-dlp PR #17826](https://github.com/yt-dlp/yt-dlp/pull/17826)，仅在插件下载实例内替换抖音提取器，不修改已安装的 yt-dlp，也不需要安装该 PR 分支。

YouTube 完整支持还需安装 [yt-dlp 支持的 JavaScript 运行时](https://github.com/yt-dlp/yt-dlp/wiki/EJS)，默认识别 Deno；Python 依赖已包含 EJS 包。

插件按需安装下载依赖，下载器与 EJS 使用配套版本。平台解析失效时，优先通过 AstrBot 插件管理更新本插件。

如需重新安装依赖，在 AstrBot 根目录使用 AstrBot 的 Python 环境执行：

```sh
python -m pip install -r data/plugins/astrbot_plugin_vision/requirements.txt
```

### 三类文件分别管理

| 文件 | 由谁保留、何时清理 |
| --- | --- |
| 直接发送的视频附件 | 由 AstrBot 管理，插件不另存副本，也不删除源视频；后续回看要求原文件仍然存在 |
| 分享链接下载的视频 | 保存在 `data/plugin_data/astrbot_plugin_vision/downloads`，同一来源复用缓存，默认容量 1024 MiB |
| 抽帧图片与 ASR 转写 | 使用插件缓存，默认容量 512 MiB；缓存可减少重复解码和转写开销 |

- **缓存清理**：默认闲置 **1 小时**到期，自动清理过期或超容量内容。命中缓存后，模型调用仍可能计费。
- **访问权限**：普通用户只能查看自己在当前会话提供且授权有效的视频，失效后需重新发送。管理员可读取 AstrBot 的 data、temp 目录中的本地视频。
- **每日额度**：普通用户默认**每人每天 5 次**，可在“视频分析 → 使用额度”调整，按**北京时间 00:00** 重置；管理员不限额。同一条消息中的多个视频和回看共用一次额度。
- **扣额规则**：开始处理视频才扣额，处理失败也计次；仅发送视频或链接不扣额，权限或参数错误也不扣额。额度用尽后，已计次问题仍可回看。重启和缓存清理不会重置用量。

## 👀 实时视觉与陪看（dev）

在插件配置中启用 **实时视觉**，重载插件，然后由 AstrBot 管理员在当前聊天发送：

```text
/live 屏幕 变化 一起看视频，遇到有意思的情节简短吐槽
/live 摄像头 提问 用户提问时描述眼前物品
/live https://example.com/live.m3u8 定时 关注比赛比分，有关键进展时提醒
/live end
```

三个参数依次是 **来源、响应模式、观察指令**；响应模式为 **提问 / 定时 / 变化**，第三个参数接收剩余文字，可包含空格，无需引号。`/live end` 结束当前聊天的会话并清理采集进程与缓冲。会话绑定发起者与当前聊天，启动需管理员权限，避免其他聊天用户远程读取宿主设备或内网地址。

本版直接采集 **运行 AstrBot 的电脑**，无需采集网页、浏览器配对、监听端口或 HTTPS。若 AstrBot 运行在服务器或容器里，“屏幕”和“摄像头”指服务器/容器可访问的设备，不会读取聊天者手机或另一台电脑。

| 来源 | 接入方式 |
| --- | --- |
| 屏幕 | FFmpeg直接采集宿主桌面：Linux X11、Windows gdigrab、macOS AVFoundation；需相应设备权限 |
| 摄像头 | 直接读取默认摄像头，可在 `live_camera_device` 指定设备 |
| 媒体URL | 第一个参数传HTTP(S)、RTSP、RTMP(S)媒体直链，FFmpeg拉流；不解析直播间网页 |

### 响应模式与配置

| 响应模式 | 观察与发言 |
| --- | --- |
| 提问 | 保留近期画面；在聊天提问，模型通过 `live_observe` 查看，仅回答用户 |
| 定时 | 按对应预设的观察间隔分析，可配置是否允许主动发言 |
| 变化 | 相邻画面、相对上次观察的累计差异或新对白出现时分析；模型认为值得评论才主动接话 |

**定时和变化模式会自动观察，需要回应时才发言。** 定时模式默认每10秒观察一次；变化模式默认最短观察间隔5秒，连续变化会合并，每会话最多一个后台视觉分析。变化分数不代表语义重要性，普通转场可以保持安静，用户对话优先。

配置按以下层级分组：

```text
实时视觉
├─ 通用设置：启用、缓冲保留时长、会话有效期、分析次数上限、主动发言冷却
├─ 设备设置：摄像头设备、音频设备
├─ 屏幕预设
│  ├─ 提问
│  ├─ 定时
│  └─ 变化
├─ 摄像头预设：提问 / 定时 / 变化
└─ 媒体 URL 预设：提问 / 定时 / 变化
```

各来源使用 AstrBot 原生模板列表，默认预置「提问／定时／变化」三个可独立展开的小组，打开配置时默认折叠，收起会保留未保存的编辑，无需修改 AstrBot 或更新前端。界面保留原生添加、删除按钮；每种响应模式只保留一项，删除条目后该模式使用默认预设，可从「添加条目」恢复。

启动 `/live` 时，按**来源 × 响应模式**选择九套预设中的一套。每套都能独立设置采样间隔（0.2～30秒）、图片长边上限（64～4096像素）、单次图片数量上限（1～32张）、取帧时间范围（0～300秒）。定时预设另有观察间隔和主动发言开关；变化预设另有变化灵敏度（low / medium / high）和最短观察间隔。采样间隔控制采集频率，观察间隔控制模型调用频率；主动发言冷却默认15秒，作用于所有来源。

九套预设的初始值如下（已有的画面尺寸、观察间隔等旧配置会迁入各套适用预设）：

| 来源 | 响应模式 | 采样间隔 | 图片长边上限 | 单次图片上限 | 取帧时间范围 |
| --- | --- | --- | --- | --- | --- |
| 屏幕 | 提问 | 1秒 | 1600 | 4张 | 0秒（最新画面） |
| 屏幕 | 定时 | 1秒 | 1600 | 2张 | 10秒 |
| 屏幕 | 变化 | 0.5秒 | 1600 | 3张 | 4秒 |
| 摄像头 | 提问 | 1秒 | 768 | 4张 | 2秒 |
| 摄像头 | 定时 | 1秒 | 768 | 4张 | 10秒 |
| 摄像头 | 变化 | 0.5秒 | 768 | 5张 | 4秒 |
| 媒体 URL | 提问 | 1秒 | 640 | 4张 | 4秒 |
| 媒体 URL | 定时 | 1秒 | 640 | 4张 | 10秒 |
| 媒体 URL | 变化 | 0.5秒 | 640 | 6张 | 6秒 |

**取帧时间范围**决定每次提交模型的图片来自最近哪段时间，同时用于自动观察和 `live_observe`。设为0只取最新一帧；工具可以通过 `lookback_sec` 临时指定本次范围，省略时使用预设。它与缓冲保留时长分开设置：取帧范围受实际缓冲限制，图片数量是上限，重复画面不会凑满数量。定时自动观察覆盖本轮观察期间；变化模式优先保留显著变化前后及最新画面，屏幕比摄像头和媒体URL采用更严格的近重复判定。图片始终保持比例且不放大小图，实时尺寸独立于离线视频的尺寸限制。

修改配置并重载插件后，新开启的会话使用新预设。升级会在加载新配置前迁移旧配置分组及实时字段，并在配置文件旁保留 `.config-groups-*.bak` 备份；命令仍只接受提问、定时、变化。

观察指令也支持操作指导，例如 `/live 屏幕 变化 教我一步步打开哔哩哔哩`：首次观察可主动给第一步，后续根据画面进展继续提示。变化模式不保证每次变化都说话。后台日志会记录观察开始、分析耗时和未发言原因（模型选择安静、冷却中、用户正在对话或采集断开等）。

每次按预设提交代表画面及对应时间、相关转写和已有观察记忆，复用“启用视频看图模型”配置：

- **启用且已选择模型**：指定看图模型先生成观察摘要，主模型只接收文字，再结合聊天上下文回复。
- **关闭或未选择模型**：`live_observe` 将图片直接提供给当前主模型，主动陪看也直接携带图片进入原对话流水线，结合当前人设和聊天历史决定回复或保持沉默，不再先调用一次独立看图请求。主模型需要支持图片；提问模式的工具直传依赖 AstrBot 内置 Agent 的运行上下文。
- **定时模式关闭主动发言**：后台仍使用指定看图模型（未指定则使用当前聊天模型）单独更新静默观察摘要，不进入发言流程；用户提问时按上述配置选择直传或转述。

直传的实时图片仅用于本轮推理，不写入持久聊天历史；文字对话由AstrBot正常保存。每个实时会话最多有一个待处理主动请求，仍检查发言冷却、画面时效和用户插话。主动评论沿用原有回复装饰、TTS、分段和平台发送设置。

### 音频与设备

ASR复用已有 `asr_enabled`、`asr_provider_id`，不增加会话音频开关。未配置ASR时只分析画面；配置后自动尝试获取音轨，按最多5秒切分16kHz单声道PCM，转WAV调用已有提供商。没有音轨或转写失败不会阻止看图。

- Linux：屏幕需要可访问的X11桌面（`DISPLAY`），纯Wayland或无桌面环境不支持该屏幕采集方式；摄像头默认 `/dev/video0`。本机音频使用系统 `parec`，屏幕默认读取播放回环，摄像头默认读取麦克风；可用 `live_audio_device` 指定PulseAudio/PipeWire source。
- Windows：摄像头默认选第一个DirectShow视频设备；音频需在 `live_audio_device` 指定DirectShow设备名，屏幕音频需系统提供回环/立体声混音设备。
- macOS：需授予运行AstrBot/FFmpeg的程序屏幕录制、摄像头、麦克风权限；屏幕音频需提供回环设备并配置索引。
- 媒体URL：尝试流内音轨。画面和音频由独立连接采集，只能粗略对齐，不保证帧级同步。台词和麦克风转写是观察资料，不作为用户指令。

### 会话限制

- 默认保留最近60秒、最多1500帧、每会话约24MiB图像字节；同时受时间、帧数和字节限制，较大图片可能提前淘汰。原始画面不持久保存，临时WAV转写后删除。正常对话历史按AstrBot设置保留。
- 超过采样有效期未收到新画面，不再作为当前事实并抑制主动评论；有效期为10秒与采样间隔3倍中的较大值。断流需 `/live end` 后重新开启。
- 采集新鲜度与推理耗时独立判断：视觉分析最多45秒，主动回复入队后最多等待45秒，证据总年龄上限90秒；保留实际证据时间，用户插话仍会作废待发回复。
- 全局最多4个会话，默认单次30分钟、最多120次视觉分析；额度独立于离线视频每日额度，ASR与主模型另按提供商计费。
- `/live end`、会话到期和插件卸载会停止采集、取消后台任务并清理缓冲。


## 🧪 在调试台里看清处理过程

在支持原生插件页面的 AstrBot WebUI 中，打开 **视频理解 → 视频流水线调试台**。上传视频后，逐步执行：

```text
视频探测 → 场景检测 → 两路候选 → 候选预合并 → 抽帧与压缩 → 邻近去重 → 最终输出 → 模型理解
```

调试台与聊天概览共用处理流水线，适合检查某一帧为什么入选、被去重，或对比模型看到的实际图片。

1. **检查抽帧**：查看场景变化分数、候选时间点、请求与实际帧时间、压缩结果，以及邻近去重的保留原因。可按需加载原分辨率对照，最终结果支持独立帧和九宫格预览。
2. **准备模型输入**：在“模型理解”中选择已配置的看图模型，填写测试问题，选择图片模式。需要语音时，勾选“加入 ASR 语音转写（仅本次测试）”，选择提供商并点击“转写音轨”。
3. **预览后调用**：先查看完整提示词、图片、时间戳和体积，再点击“调用模型”。页面展示回答、耗时及供应商返回的 token 用量，支持选择两条记录比较、导出 JSON。

**前七步本地处理和输入预览不会调用模型，也不会自动调用 ASR。**

全局最多保留 **4 个测试会话**。每个会话最多保存 **20 条模型记录和 20 条转写记录**，闲置到期或插件重载后清理；重跑会清空旧记录和图片，需要留存时请先导出。

## 🩺 遇到问题时

**找不到 FFmpeg 或 ffprobe**：检查 AstrBot 所在进程或容器是否能执行两个命令。桌面系统中安装成功，不代表容器或服务进程也能找到；必要时在“基础依赖”中填写绝对路径。

**分享链接下载失败**：先检查链接是否有效、网络是否可达、平台是否要求登录，再检查 Cookie、yt-dlp 版本和 YouTube 的 JavaScript 运行时。使用 Fake-IP DNS 时按前文启用兼容；也可以直接发送视频附件。

**抖音解析失败或提示 Fresh cookies**：公开视频会先自动补齐匿名访问凭据与签名。失败可能来自平台风控、视频不可用或签名规则变化，不能仅凭 Fresh cookies 判断 Cookie 过期。先检查链接、更新插件和 yt-dlp；仍失败时，可在浏览器打开视频并完成平台验证，再导出 Netscape 格式 Cookie 文件，填写到 **yt-dlp Cookie 文件路径**，或直接发送视频附件。

**模型报图片过多、上下文过长或超时**：降低概览帧数预算、增加采样间隔或减小单帧尺寸；也可尝试九宫格或单独看图模型。转述会把视觉开销交给所选模型，同时增加文字输入，不保证总费用更低或速度更快。

**回看找不到旧视频**：可能是 AstrBot 已清理附件、分享下载缓存过期、文件变化或会话授权失效。重新发送附件或分享来源，再获取概览。

**主模型只拿到文字**：检查是否启用了视频看图模型，这是转述模式的预期行为。关闭后，概览和回看均由主模型直接看图；直接传图依赖内置 Agent 的 `on_agent_begin` 运行上下文，不支持第三方 Agent 后端。

## 🛠️ 工具与开发参考

<details>
<summary>展开模型工具参数与返回约定</summary>

### 全片概览：video_overview

`video_path` 接受视频资源提示中的真实本地路径，或分享来源的 `source_id`，不直接接受网址。分享视频下载成功后，结果会提供本地 `video_path`，后续回看使用这个路径。

```json
{"video_path": "/AstrBot/data/temp/example.mp4"}
```

### 局部回看：video_inspect

查看动作过程时用 `range`，`times_sec` 必须恰好包含起止时间：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "range",
  "times_sec": [12, 16],
  "max_frames": 8,
  "max_edge": 768
}
```

查看指定时刻时用 `timestamps`，`times_sec` 为非空时间点列表：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "mode": "timestamps",
  "times_sec": [12.5, 14, 15.8],
  "max_frames": null,
  "max_edge": 1280
}
```

`max_frames`、`max_edge` 填 `null` 使用配置值。尺寸保持比例，不放大小图，并受服务端上限约束。

所有时间都按原视频时间轴计算，实际帧时间可能与请求略有差异，应以 `timestamp_sec` 为准。

参数错误会返回 `INVALID_ARGUMENT`、调用示例和剩余次数，不消耗回看次数；处理失败或超时仍计入次数。

同一问题中不会重复生成同一视频概览。

</details>
