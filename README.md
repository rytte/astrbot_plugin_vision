# 视频理解 · astrbot_plugin_vision

为 AstrBot 主对话模型提供两个工具：先获取视频概览，再按需要回看指定时间段。默认由主模型直接看图，也可从 AstrBot 已配置的模型中指定概览看图模型，无需在插件中另填 API Key。

## 工作方式

```text
接收视频并获取本地路径
    → 固定间隔帧 + 场景变化候选 + 边界帧
    → 邻近去重、时间覆盖检查、帧数预算
    → 默认将图片及真实时间戳交给主模型
      或由指定看图模型生成文字概览，再交给主模型
    → 证据不足时按时间点或时间段回看
```

- 概览默认每 **4 秒**采样，最终最多 **200 帧**，图片长边最多 **640 像素**。
- 超预算时增大固定间隔，仍覆盖全片，不直接丢弃后半段。
- 场景变化检测在本地完成；候选不等于编码关键帧，也不保证语义重要。
- 时间接近且内容相似时，优先保留清晰、有效的变化帧；存在明显差异或会破坏覆盖时保留必要帧。不对全片做无条件相似帧去重。
- 回看默认最多 **8 帧**、长边 **768 像素**；每个问题最多 **3 次**，多个视频共享次数。执行失败也计入次数，避免无限重试。
- 直接看图模式和局部回看的真实图片通过 AstrBot 内置 Agent 的运行上下文传入主模型，每张图片前附帧信息和时间戳；工具结果只返回元数据，不触发核心为 `ImageContent` 添加的缓存路径及“满意后发给用户”提示。

## 安装

1. 使用 AstrBot `>=4.27,<5`，将本仓库作为插件安装到 `data/plugins/astrbot_plugin_vision`。
2. 安装 `requirements.txt` 中的 Python 依赖。
3. 在 **AstrBot 实际运行环境**安装 FFmpeg，确保同时包含 `ffmpeg` 和 `ffprobe`。容器部署必须安装在容器内，而不是只安装在宿主机。
4. 使用 AstrBot 内置 Agent，确认主模型支持图片和工具调用，并启用 `video_overview`、`video_inspect`。本插件依赖 `on_agent_begin` 提供的运行上下文传入视频帧；缺少该上下文时明确报错，不支持第三方 Agent 后端。

检查依赖：

```text
ffmpeg -version
ffprobe -version
```

默认从 `PATH` 查找，也可在插件配置中指定 `ffmpeg_path`、`ffprobe_path`。路径填写可执行文件本身，不要填写带参数的命令，也不需要额外加引号。

## 使用

直接向机器人发送视频并提出问题。插件在模型请求前读取视频附件的本地路径，将可用路径附加到当前问题中，不主动进行模型分析。引用消息里的视频、常见视频扩展名的文件附件也会尝试读取。

### `video_overview`

```json
{"video_path": "/AstrBot/data/temp/example.mp4"}
```

返回视频元信息、采样策略、预算是否导致降采样、实际最大采样间隔，以及按时间排序的图片。每张图片附带 `frame_id`、请求时间、实际时间和入选原因；逐帧描述不重复附带宽高。

在插件配置的 **“概览看图模型（可选）”** 中，可使用 AstrBot 原生模型选择器选择已配置且支持图片的模型：

- **留空**：维持默认行为，主模型直接接收概览图片，`overview_mode` 为 `direct`。
- **已选择**：指定模型接收全部概览帧、时间戳和当前问题，生成带时间定位的文字描述；主模型只接收文字概览及帧索引，`overview_mode` 为 `delegated`。
- 该配置仅影响 `video_overview`；`video_inspect` 始终返回原图给主模型，主模型仍需支持图片输入。
- 指定模型不接收完整聊天历史、人设或工具。其描述属于二手观察，可能遗漏或误解细节，需要时应回看原图核验。
- 模型调用失败、返回空描述或超时会明确报错，**不会自动回退成主模型看概览图片**，避免意外的大量图片输入。抽帧和模型调用共用单次工具超时。

### `video_inspect`

查看动作过程：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "start_sec": 120,
  "end_sec": 124,
  "max_frames": 8,
  "max_edge": 768
}
```

核实指定时刻：

```json
{
  "video_path": "/AstrBot/data/temp/example.mp4",
  "timestamps_sec": [120.5, 121.8, 123],
  "max_edge": 1280
}
```

时间范围和时间点列表不能同时使用。所有时间以原视频时间轴为准，从 0 秒开始；实际帧可能略晚于请求时间，尾部可能回退至可读取的帧，因此应以返回的 `timestamp_sec` 为准。重复落到同一帧时只返回一次。

`max_edge` 是模型请求的图片最长边上限，保持比例、不放大小图，并受服务端硬上限约束。查看小字可以提高尺寸；没采到动作过程则应缩小时间范围或增加采样帧数。同一问题内已返回的相同尺寸、相同画面帧不会重复送图，相同视频概览也不会重复生成。

## 配置

| 配置 | 默认值 | 用途 |
|---|---:|---|
| `ffmpeg_path` / `ffprobe_path` | 空 | 留空从 PATH 查找 |
| `allowed_video_roots` | `[]` | 额外允许读取的已有绝对目录 |
| `overview_provider_id` | 空 | 概览看图模型，使用 AstrBot 已配置模型的选择器；留空由主模型直接看图 |
| `overview_interval` | 4 | 概览默认间隔，单位秒 |
| `overview_max_frames` | 200 | 概览总帧数上限 |
| `overview_max_edge` | 640 | 概览图片长边像素上限 |
| `scene_threshold` | 0.3 | 场景变化阈值，越低越敏感 |
| `inspect_max_frames` | 8 | 单次回看帧数硬上限 |
| `inspect_max_edge` | 768 | 回看默认图片长边上限 |
| `max_edge_limit` | 1280 | 所有尺寸请求的长边硬上限 |
| `inspect_max_calls` | 3 | 单个问题的回看次数上限 |
| `tool_timeout` | 300 | 单次工具总超时，单位秒 |
| `max_concurrency` | 2 | 工具及子进程并发上限 |
| `cache_ttl` | 3600 | 缓存闲置期限与视频授权期限，单位秒 |
| `cache_max_mb` | 512 | 空闲清理后的缓存容量上限，单位 MB |

配置项和服务端上限可按模型能力调整。**200 帧是图片数量上限，不是 token 上限，也不保证所有模型接口都能接收。**如果模型限制图片数量或上下文长度，请调低概览预算。缓存可减少本地解码开销，不代表新问题里的图片输入不计费。

指定概览模型后，图片 token 开销转移到所选模型，主模型还会消耗文字概览及局部回看的 token。选择更便宜的看图模型可能降低费用，但多出一次模型调用，不保证总费用更低或速度更快。

## 文件和权限边界

- 仅接收本地视频路径，不通过工具下载网址，也不支持 B 站链接或网络共享路径。视频附件的落盘由 AstrBot 消息组件负责。
- 默认允许 AstrBot 的 data、temp 目录。其他位置需要加入 `allowed_video_roots`；路径会规范化并检查真实位置，不能通过 `..` 或符号链接逃出允许目录。
- 普通用户只能访问自己在同一会话提供、且仍在授权有效期内的视频；更换用户或会话不能借用该路径。管理员可直接传入允许目录内的视频路径。
- 文件发生变化后，普通用户需要重新发送以授权；缓存按路径、大小和修改时间区分。
- 使用参数列表调用 FFmpeg，不拼接 Shell 命令；解码限定本地协议及常见视频容器，不接受播放列表作为输入。
- 只清理插件自己的抽帧缓存，不删除源视频。上游必须保证回看时源文件仍存在；插件重载会清空会话授权，必要时请重新发送视频。
- 视频内容是不可信资料，不能当作系统或工具指令。稀疏采样没有看到某事件，不足以证明事件没有发生；预算耗尽仍不确定时应明确说明。

首版不包含音频转写、专门的字幕 OCR 或语义搜索；支持可选概览看图模型，不额外实现多级视觉分析流水线。

## 开发验证

使用包含 AstrBot、Pillow、pytest、pytest-asyncio 的环境运行：

```text
python -m pytest tests -q
ruff check .
ruff format --check .
```

测试包含采样覆盖与预算、邻近去重、路径及会话权限、回看次数、直接看图与指定模型概览、Agent 工具循环中的图片输入与提示隔离、模型失败及取消、真实 FFmpeg 场景检测与时间戳、缓存和子进程取消。模型接口使用模拟响应，未安装 FFmpeg 时，真实视频测试会跳过。
